# Canva 가이드형 디자인 워크플로우 (카드뉴스 외)

이 스킬은 Canva MCP 도구를 통해 주제 하나를 사용자의 실제 Canva 계정 안의
완성된 디자인으로 만들어냅니다. 모든 생성·리사이즈·내보내기·폴더 변경은
사용자가 그냥 버릴 수 있는 로컬 파일이 아니라 제3자 서비스 계정에서 실제로,
눈에 보이게 일어나는 작업이기 때문에, 이 워크플로우는 단번에 끝까지
진행하기보다 명확한 체크포인트를 중심으로 설계되어 있습니다. "시간을
아끼려고" 체크포인트를 건너뛰면 사용자가 실제로 승인하지 않은 디자인이
만들어지게 되며, 이를 되돌리는 데 드는 시간이 체크포인트 하나를 지키는
것보다 훨씬 큽니다.

## 4개의 체크포인트

아래 지점에서는 사용자의 명확한 응답(침묵이나 애매한 답변 제외) 없이는
절대 다음 단계로 넘어가지 마세요.

1. **컨셉 승인** — 디자인 컨셉을 제안한 뒤, Canva에 무언가가 생성되기 전.
2. **후보 선택** — `generate-design`이 후보를 반환한 뒤,
   `create-design-from-candidate`로 하나를 확정하기 전.
3. **초안 검토** — 초안의 편집 링크를 공유한 뒤, 해당 디자인에 추가 작업을
   하기 전(사용자 본인의 검토 의견, 예: "이거 별로야", "이 부분 바꿔줘",
   또는 승인이 있을 때만 진행).
4. **저장/내보내기 승인** — 사용자가 실제로 저장/확정을 말했을 때만
   (예: "저장해줘", "이걸로 확정") 내보내기 및 정리를 진행.

## 1단계 — 주제 파악 및 컨셉 도출

주제가 주어지지 않았다면 먼저 물어봅니다. 그다음 **최소 3가지의 뚜렷이
구분되는 컨셉**을 도출합니다 — 단순히 문구만 다른 게 아니라 구성·톤·컬러
방향이 달라야 합니다. 채팅에 한눈에 훑어볼 수 있는 형태로 제시하세요
(어떤 페이지/카드로 구성되는지, 비주얼 무드, 어떤 대상을 위한 것인지).
이 단계에서는 아직 어떤 Canva 도구도 호출하지 않습니다 — 컨셉은 실제로
생성되기 전까지 자유롭게 수정할 수 있어야 합니다.

## 2단계 — 작업물 종류 확인

컨셉이 정해지면, 요청에서 이미 명확하지 않은 이상 어떤 종류의 작업물을
원하는지 확인합니다(카드뉴스, 포스터, 프레젠테이션, 단일 소셜 게시물 등).
이는 `generate-design`에 전달할 `design_type`을 결정합니다 — 여러 장으로
구성되는 "카드뉴스"는 `design_type: presentation`에 매핑됩니다. 하나의
디자인 안에서 여러 페이지/슬라이드를 지원하는 유일한 타입이기 때문입니다.

기존 브랜드 킷을 따르는 디자인을 원하는지는 짐작하지 말고 먼저 물어본 뒤에만
`list-brand-kits`를 호출하세요. 사용자가 브랜드 킷을 고른 뒤에만
`generate-design`에 `brand_kit_id`를 전달합니다.

## 3단계 — 후보 생성

승인된 컨셉을 상세히 설명하는 쿼리로 `generate-design`을 호출합니다:
페이지 수, 각 페이지에 들어갈 내용, 컬러 팔레트, 폰트/타이포그래피
스타일까지 포함하세요. 작성 언어는 사용자의 디자인 언어와 맞춰야 하며
(한국어 주제라면 보통 한국어), 도구가 특정 언어를 기본값으로 사용하지
않으므로 쿼리에 명시적으로 언급해야 합니다.

**알려진 제약: 후보 개수는 고정되어 있습니다.** `generate-design`에는
후보 개수를 지정하는 파라미터가 없습니다 — 테스트에서는 요청 문구를
어떻게 바꾸든 항상 정확히 4개가 반환되었습니다. 사용자가 특정 개수의
후보를 요청하면, 도구가 반환하는 개수를 조용히 그대로 주지 말고 이것이
도구 자체의 제약이라는 점을 먼저 알려주세요 — 무시한 게 아니라는 걸
사용자가 알아야 합니다.

후보 썸네일/링크를 제시하고 **사용자가 하나를 고를 때까지 기다립니다**
(체크포인트 2).

## 4단계 — 선택한 후보 확정

선택된 `candidate_id`와 생성 호출에서 받은 `job_id`로
`create-design-from-candidate`를 호출합니다. 이 시점부터 디자인이 실제로
편집 가능한 Canva 항목이 됩니다 — 그 이전까지는 모두 미리보기에
불과합니다.

## 5단계 — 비율 조정 (요청이 있을 때만)

**알려진 제약: 비율은 생성 시점에 설정할 수 없습니다.**
`generate-design`에는 비율 파라미터가 없어서, 모든 후보는 해당 디자인
타입의 기본값(예: 프레젠테이션은 16:9)으로 나옵니다. 기본값이 아닌 비율은
확정된 디자인에 대해서만 `resize-design`으로 적용할 수 있습니다 — 프리셋은
`presentation`/`whiteboard`만 지원하므로, 그 외(4:3, 정사각형 등)는
`type: custom`으로 픽셀 단위 `width`/`height`를 직접 지정해야 합니다.
사용자가 후보 단계부터 비율이 반영되길 기대한다면 이 순서를 설명해주세요
— 실제로 적용할 수 있었던 시점보다 더 일찍 적용한 것처럼 말하지 마세요.

## 6단계 — 초안 공유 및 검토 대기

디자인의 `edit_url`을 확인 링크로 사용자에게 전달합니다(체크포인트 3).
사용자가 피드백이나 승인으로 응답하기 전까지는 해당 디자인을 더 이상
건드리지 마세요 — 이는 사용자가 정적인 미리보기가 아니라 실제 편집 가능한
Canva 파일을 처음으로 확인하는 시점입니다.

## 7단계 — 외부 참고 이미지 (요청이 있을 때만)

Canva MCP에는 웹이나 스톡 사진 검색 도구가 없습니다 — `get-assets`는 이미
계정에 업로드된 것만 조회합니다. 사용자가 실제 사진, 로고, 기타 참고
이미지 삽입을 원한다면:

1. `WebSearch`/`WebFetch`로 실제 공개 출처(공식 사이트, 위키피디아 등)를
   찾습니다 — URL을 절대 지어내거나 추측하지 마세요.
2. 후보 URL이 실제로 이미지 콘텐츠로 연결되는지(예: HEAD 요청) 사용 전에
   검증합니다 — 웹페이지 링크와 다이렉트 이미지 파일 링크는 다르며,
   `upload-asset-from-url`에는 후자가 필요합니다.
3. `upload-asset-from-url`로 업로드한 뒤, 반환된 asset id를
   `generate-design`의 `asset_ids` 파라미터로 전달합니다(즉 이미지는
   기존 디자인에 나중에 끼워 넣는 게 아니라 생성 *전에* 미리 확보해야
   합니다).
4. 신뢰할 수 있는 다이렉트 이미지 URL을 찾지 못하면 건너뛰고, 무엇을 왜
   건너뛰었는지 사용자에게 명확히 알립니다. 요청을 조용히 무시하거나,
   검증되지 않은/지어낸 링크로 대신 채우지 마세요.

## 8단계 — 저장/내보내기 (체크포인트 4)

사용자가 저장 또는 확정을 명시적으로 승인했을 때만 진행합니다. 그 다음:

1. 먼저 해당 디자인에 대해 `get-export-formats`를 호출합니다 — 포맷
   지원 여부를 절대 짐작하지 말고, 사용자가 요청한 포맷이라고 해서
   지원된다고 가정하지 마세요.
2. 사용자가 다른 포맷을 요청하지 않았다면 `format.type: "png"`로
   `export-design`을 호출합니다(이 스킬의 기본 출력 확장자).

## 9단계 — Canva 폴더로 정리

완성된 작업물은 예측 가능한 구조로 관리합니다: 최상위 `canva` 폴더 아래에
주제별 하위 폴더를 둡니다.

1. `search-folders`로 `canva`라는 이름의 폴더를 찾고, 검색 결과가 없을
   때만 `create-folder`(`root`에)를 호출합니다 — 중복 생성하지 마세요.
2. 그 안의 주제별 하위 폴더에도 동일하게 확인 후 생성 패턴을 적용합니다.
3. 확정된 디자인을 `move-item-to-folder`로 주제 하위 폴더로 이동합니다.

## 10단계 — 결과 보고

사용자가 다시 물어보지 않고도 디자인을 찾을 수 있도록 PNG 내보내기
링크와 Canva 폴더 링크를 전달합니다.

## 핵심 원칙

위의 "알려진 제약"들은 우선순위가 낮아서가 아니라 도구가 실제로 아직 그
기능을 지원하지 않기 때문에 존재합니다. 이런 제약을 만나거나, 사용자가
요청한 것과 실제로 가능한 것 사이에 다른 간극이 생기면(지원되지 않는
포맷, 구할 수 없는 이미지, 프리셋에 맞지 않는 크기 등) **멈추고, 구체적인
간극을 설명하고, 대안에 대해 사용자의 승인을 받은 뒤에 진행하세요.**
비슷한 것으로 조용히 대체하거나 요청의 일부를 조용히 빠뜨리는 것은
질문하는 것보다 훨씬 나쁩니다 — 사용자는 자신의 실제 Canva 계정에서
작업하고 있으며, 실제로 무슨 일이 일어났는지 알아야 합니다.

## 예외 상황

- **진행 중 사용자가 컨셉이나 작업물 종류를 바꾸는 경우**: 그 부분은
  1/2단계부터 다시 시작하는 것으로 취급하세요 — 이미 생성된 후보를 다른
  컨셉에 억지로 맞추려 하지 마세요.
- **사용자가 체크포인트를 건너뛰라고 요청하는 경우** ("그냥 다
  진행해줘"): 이는 *남은* 단계들을 매번 다시 묻지 않고 진행하도록
  허용하는 것이지만, 저장/내보내기 체크포인트(8단계)는 별도의 명확한
  트리거("저장해줘"/"승인"/이에 준하는 표현)가 필요합니다 — 사용자의
  표현이 그 부분까지 명확히 포함하지 않는 한, 일반적인 "나머지 진행해줘"가
  이 단계까지 포함한다고 간주하지 마세요.
- **하나의 주제로 여러 디자인을 만드는 경우**(예: 카드뉴스 + 같은 톤의
  포스터): 각 작업물 종류마다 컨셉 → 후보 → 초안 → 저장 루프를 별도로
  진행하세요 — 하나의 `generate-design` 호출로 합치지 마세요.
