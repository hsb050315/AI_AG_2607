# 뉴스 스크랩 → 보고서 + 발표자료 생성

주제(또는 기사 URL 목록) 하나를 받아 (1) Playwright MCP로 실제 기사 페이지 스크랩(스크린샷) → (2) 스크랩 내용 분석 → (3) `.docx` 보고서 조립 → (4) `.pptx` 발표자료 조립까지 끝내는 스킬이다. 문서/발표자료 조립 코드를 매번 새로 짜지 말고, 번들된 스크립트와 sibling 스킬의 스크립트를 그대로 가져다 쓴다.

## 전체 흐름

1. **범위 확정** — 주제(또는 URL 목록), 스크랩할 기사 개수가 요청에서 충분히 명확하면 바로 진행한다. 기사 개수를 특정하지 않았으면 기본 3~5개로 진행한다(주제가 매우 광범위하면 5개, 구체적이면 3개 정도로 판단). 기사 검색/탐색은 항상 네이버 뉴스로만 제한한다 — 다른 뉴스 사이트(구글 뉴스, 다음 뉴스, 언론사 자체 홈페이지 등)에서 기사를 검색하거나 둘러보지 않는다. 사용자가 특정 기사 URL을 직접 준 경우 검색 단계를 생략하고 어떤 사이트의 URL이든 바로 스크랩한다.

2. **Playwright MCP로 기사 탐색 및 스크랩** — Playwright MCP 도구(`mcp__playwright__browser_navigate`, `browser_find`, `browser_snapshot`, `browser_click`, `browser_take_screenshot` 등)를 사용한다. 도구가 deferred 상태면 먼저 ToolSearch로 로드한다.
   - **네이버 뉴스 검색**: `https://search.naver.com/search.naver?where=news&query=<검색어>` 로 이동하거나, 네이버 뉴스 섹션(`https://news.naver.com/section/<sid>`) 또는 언론사 목록(`https://news.naver.com/main/list.naver?mode=LSD&mid=sec&sid1=<sid>`)을 활용해 관련 기사를 찾는다.
     - 참고 섹션 코드: 정치 100 / 경제 101 / 사회 102 / 생활문화 103 / 세계 104 / IT과학 105.
     - `news.naver.com/section/<sid>` 계열의 "기사 더보기" 버튼은 실제로 새 기사를 계속 추가하지 않고 정해진 풀(약 50~60개) 안에서만 동작할 수 있다 — 진짜 페이지 번호가 필요하면 `news.naver.com/main/list.naver?mode=LSD&mid=sec&sid1=<sid>` 형태의 목록 페이지(번호 pagination 1,2,3...이 실제로 존재)를 사용한다.
     - 기사를 찾을 때 네이버 뉴스 외의 검색엔진이나 뉴스 사이트(구글 뉴스, 다음 뉴스, 언론사 자체 사이트 등)는 사용하지 않는다 — 탐색용 소스는 네이버 뉴스뿐이다.
   - **범용 URL**: 사용자가 특정 뉴스 사이트나 기사 URL을 줬다면 네이버 여부와 관계없이 그 URL로 바로 이동해 스크랩한다.
   - 각 기사마다:
     1. 기사 페이지로 이동한다.
     2. `browser_take_screenshot`을 `fullPage: true`로 호출해 전체 페이지를 캡처한다. 저장 경로는 아래 "출력 위치" 규칙을 따른다.
     3. 기사 본문 텍스트를 파악한다 (`browser_snapshot` 또는 페이지 텍스트 추출) — 다음 분석 단계에서 요약에 쓴다. 스크린샷은 증거자료이지 분석 대상 텍스트 추출 수단이 아니므로, 실제 요약은 페이지에서 읽은 텍스트를 근거로 작성한다.
     4. 기사 제목, 언론사, URL, 스크린샷 파일 경로를 기록해둔다 (보고서/발표자료 조립 시 필요).

3. **분석** — 스크랩한 기사들을 종합해 다음을 정리한다:
   - 기사별 핵심 요약 (2~4문장 또는 3~5개 불릿)
   - 기사들을 관통하는 공통 트렌드/이슈, 상충되는 관점이 있다면 그것도 명시
   - 결론 및 시사점

4. **`.docx` 보고서 조립** — sibling 스킬 `docx-research-report`의 `scripts/docx_generator.py`를 그대로 import해서 사용한다 (같은 `.claude/skills/` 아래에 있으므로 상대 경로로 접근 가능). 직접 저수준 python-docx 코드를 새로 짜지 않는다.

   ```python
   import sys
   sys.path.insert(0, "<프로젝트 루트>/.claude/skills/docx-research-report/scripts")
   from docx_generator import (
       new_document, add_title, add_heading, add_paragraph,
       add_bullet_list, add_table, add_image, add_divider,
       set_margins, add_page_number_footer, save,
   )

   doc = new_document(main_color="1F4E79")
   set_margins(doc)
   add_page_number_footer(doc)
   add_title(doc, "OO 뉴스 스크랩 보고서", subtitle=f"조사일자: {오늘 날짜} | 스크랩 기사 {N}건")

   add_heading(doc, "1. 개요", level=1)
   add_paragraph(doc, "...")

   add_heading(doc, "2. 기사별 요약", level=1)
   # 기사마다: 소제목(add_heading level=2) → 요약(add_paragraph/add_bullet_list) → 스크린샷(add_image) → 출처(add_paragraph)

   add_heading(doc, "3. 종합 인사이트", level=1)
   add_paragraph(doc, "...")

   add_heading(doc, "4. 결론 및 시사점", level=1)
   add_paragraph(doc, "...")

   save(doc, "output/reports/OO_뉴스_스크랩_보고서.docx")
   ```

   docx-research-report 스킬과 동일하게, `.docx`와 내용이 같은 순수 텍스트 `.txt` 버전도 같은 basename으로 함께 만든다(표/이미지는 텍스트로는 캡션·경로만 표기).

5. **`.pptx` 발표자료 조립** — 이 스킬에 번들된 `scripts/pptx_generator.py`를 사용한다. 목표 수준은 심플 템플릿(제목/요약 불릿 + 스크린샷 썸네일)이다 — 차트나 복잡한 커스텀 레이아웃을 추가하려 하지 않는다.

   ```python
   import sys
   sys.path.insert(0, "<이 스킬 폴더>/scripts")
   from pptx_generator import (
       new_presentation, add_title_slide, add_section_slide,
       add_bullet_slide, add_image_bullet_slide, add_closing_slide, save,
   )

   prs = new_presentation(main_color="1F4E79")
   add_title_slide(prs, "OO 뉴스 스크랩 브리핑", subtitle=f"조사일자: {오늘 날짜}")

   add_section_slide(prs, "기사별 요약")
   # 기사마다 한 슬라이드: add_image_bullet_slide(prs, 기사제목, [핵심요약 불릿...], 스크린샷_경로, source="출처: 언론사 · 날짜")

   add_section_slide(prs, "종합 인사이트")
   add_bullet_slide(prs, "종합 결론", ["트렌드/시사점 불릿..."])

   add_closing_slide(prs)
   save(prs, "output/presentations/OO_뉴스_스크랩_브리핑.pptx")
   ```

   `main_color`는 `.docx` 보고서와 동일한 색으로 맞춰 두 산출물의 톤을 통일한다.

6. **결과 보고** — 저장된 스크린샷 경로들, `.docx`/`.txt`/`.pptx`의 절대 경로를 사용자에게 정리해서 알려준다.

## 출력 위치

이 프로젝트(AI_AG_2607)의 `output/` 폴더 규칙을 따른다:

- 스크린샷(Playwright MCP로 캡처한 것) → `output/screenshots/`
- `.docx`/`.txt` 보고서 → `output/reports/`
- `.pptx` 발표자료 → `output/presentations/` (기존에 없으면 새로 만든다 — pptx는 기존 하위 폴더 어디에도 해당하지 않는 새로운 종류의 산출물이다)

다른 프로젝트에서 이 스킬을 쓸 경우 `output/` 폴더가 없으면 위 하위 폴더 구조 그대로 새로 만들어서 저장한다.

## 파일명 규칙

- 스크린샷: `<기사 제목 또는 언론사+번호>.png` (파일명에 쓸 수 없는 특수문자는 언더스코어로 치환)
- 보고서/발표자료: `<주제(공백은 언더스코어로)>_뉴스_스크랩_보고서.docx` / 같은 basename `.txt` / `<주제>_뉴스_스크랩_브리핑.pptx`

## 하지 말아야 할 것

- 스크린샷 없이 검색 스니펫이나 기존 지식만으로 기사 내용을 요약하지 않는다 — 이 스킬의 핵심은 실제 페이지를 열어서 스크랩한 증거를 남기는 것이다.
- 보고서와 발표자료 중 하나만 만들고 끝내지 않는다 — 사용자가 명시적으로 하나만 요청한 게 아니라면 둘 다 만든다.
- `.docx`/`.pptx` 조립에 저수준 코드를 새로 작성하지 않는다 — 번들/sibling 스크립트의 함수를 조합해서 쓴다.
- python-pptx가 설치되어 있지 않으면(`ModuleNotFoundError: No module named 'pptx'`) `pip install python-pptx`로 설치 후 진행한다.
