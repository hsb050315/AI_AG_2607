# references: 실사례 디자인 레퍼런스 수집기

디자인 컨셉이나 몇 개의 디자인 키워드를 받으면, 거기에 맞는 **실제 완성된 디자인 작업물** — 실제 랜딩 페이지, 포스터, 덱, 브랜드 시스템, 편집 레이아웃 — 을 브라우저로 디자인 갤러리를 탐색하며 찾아내고, 각각을 스크린샷 + 짧은 선정 근거로 저장한다. 목적은 잘라낸 조각들의 무드 콜라주가 아니라, "다른 사람들은 비슷한 브리프를 이렇게 풀었다"를 보여주는 작고 엄선된 보드를 팀에 남기는 것이다.

채팅으로 답하는 대신 이 스킬을 트리거할 가치가 있는 이유는 두 가지다: 레퍼런스는 **실제 공개 작업물의 진짜 스크린샷**(설명이 아니라 증거)이어야 하고, 각 선정은 디자이너가 그 보드를 신뢰할 수 있도록 **왜 맞는지에 대한 문서화된 근거**가 필요하다.

## 입력: 컨셉 문서 또는 키워드

이 스킬은 둘 중 하나를 받으며, 흔히 둘 다 받는다:

- **`design-concept` Google 문서 URL** (`design-concept` 스킬이 생성). `WebFetch`로 읽는다. 문서가 공개 공유되어 있지 않아 WebFetch가 쓸 만한 내용을 반환하지 못하면, 사용자에게 무드·톤앤매너 / 컬러 팔레트 / 주제 섹션을 붙여넣어 달라고 하거나, `gws` CLI가 설정되어 있으면 그것으로 읽는다. 다음을 뽑아낸다: 주제, 무드 키워드 3~5개, 팔레트(색상명 + HEX), 명시되어 있으면 매체.
- **채팅의 자유 입력 키워드** (예: "미니멀한 핀테크 앱", "손으로 만든 느낌의 베이커리 브랜드"). 그대로 사용한다.

둘 다 있으면 문서가 기준이고, 채팅에서 나온 추가 디테일은 검색에 반영한다.

거의 정보가 없으면(모호한 단어 하나, 매체 불명) 짧게 한 가지만 묻는다 — 어떤 매체인지(웹 / 포스터 / 덱 / 패키지 / 브랜드), 주제가 있는지. 그 외에는 합리적으로 판단하고 그 가정을 .txt에 적어둔다.

## 흐름

### 1. 컨셉을 검색 입력값으로 변환

브라우저를 열기 전에 이것들을 적어둔다:

- **매체** — 웹 페이지, 랜딩 페이지, 포스터 / 키비주얼, 슬라이드 덱, 패키지, 편집물, 전체 브랜드 아이덴티티. 어떤 갤러리를 쓸지가 여기서 결정된다.
- **검색어 3~6개** — 영어와 한국어를 섞고, 컨셉 단어와 구체적 서술어를 섞는다: "warm handmade bakery branding", "베이커리 브랜딩", "artisan food packaging minimal". 갤러리는 대부분 영어로 색인되므로 영어 표현을 앞세운다.
- **목표 개수** — 기본 **최종 5건**(후보 8~12건을 훑고 그중 가장 좋은 5건을 남긴다). 사용자가 숫자를 줬으면 그것을 쓴다.

### 2. 매체에 따라 갤러리 선택

| 매체 | 갤러리 (이 순서로 탐색) |
|---|---|
| 웹 / 랜딩 / UI | Land-book (land-book.com), Godly (godly.website), Awwwards (awwwards.com), SiteInspire (siteinspire.com), GDWEB (gdweb.co.kr — 한국 시장) |
| 포스터 / 키비주얼 / 그래픽 | Behance (behance.net), Pinterest (pinterest.com), Savee (savee.it), Notefolio (notefolio.net — 한국) |
| 슬라이드 덱 / 피치 덱 | Behance ("pitch deck", "presentation design"), Dribbble (dribbble.com), Pinterest |
| 패키지 | Behance, Pinterest, The Dieline (thedieline.com) |
| 편집물 / 브랜드 아이덴티티 | Behance, Pinterest, Savee, Notefolio |

Behance, Land-book, Godly, Awwwards, SiteInspire, GDWEB, The Dieline은 로그인 없이 잘 탐색된다. Pinterest와 Dribbble은 더 깊은 탐색을 로그인 벽 뒤에 두기도 한다 — 검색 결과 그리드에 보이는 것만 취하고, 인증이 필요 없는 개별 핀 / 샷만 연다. **절대 로그인하지 말고 계정을 만들지 마라.**

### 3. Playwright MCP로 탐색

`mcp__playwright__browser_navigate`, `browser_snapshot`, `browser_find`, `browser_click`, `browser_take_screenshot`를 사용한다. 지연 로딩(deferred) 상태면 ToolSearch로 불러온다.

- 쿠키 / 동의 배너에서는 가장 프라이버시 보호적인 옵션을 고른다(필수 외 거부). "모두 허용"을 누르지 마라.
- 대부분의 갤러리에는 검색창이나 URL 검색 패턴이 있다(예: `behance.net/search/projects?search=<query>`, `land-book.com/?search=<query>`). 이동해서 `browser_snapshot`으로 그리드를 훑고, 주제뿐 아니라 진짜로 *컨셉*에 맞는 후보를 고른다 — 시끄럽고 장난스러운 핀테크 사이트는 "절제된 신뢰감"의 매치가 아니다.
- 각 후보의 상세 페이지(실제 프로젝트 / 사이트 페이지)를 연다. Awwwards나 Land-book에서 링크된 라이브 사이트는 실제 사이트를 열어 실물을 스크린샷 찍어도 된다.

### 4. 조각이 아니라 전체 디자인을 캡처

사용자는 완결된 레이아웃을 원한다. 남기는 레퍼런스마다:

- 웹 페이지: `browser_take_screenshot`에 `fullPage: true`를 줘서 스크롤 전체를 한 이미지에 담는다.
- 포스터 / 덱 / 패키지: 전체 구성을 프레임에 담는다. 갤러리가 한 프로젝트에 여러 이미지를 보여주면, 디테일 크롭이 아니라 전체 레이아웃이 보이는 1~2장을 찍는다.
- `browser_take_screenshot`의 `filename`으로 저장한 뒤, 파일을 제자리로 옮긴다(아래 참고).
- 각각에 대해 기록한다: 짧은 이름, 갤러리, 표시되어 있으면 제작자 / 스튜디오, **상세 페이지 URL**과 있으면 **실제 사이트 URL**, 그리고 *왜 이 컨셉에 맞는지* 1~2문장 — 어떤 무드 키워드인지, 색 / 타이포 / 레이아웃의 무엇이.

### 5. 저장

- 스크린샷 → `output/references/image/<topic-slug>/`, 이름은 `NN_<gallery>_<short-name>.png` (예: `01_landbook_oat-milk-bakery.png`). `<topic-slug>`은 컨셉의 짧은 ASCII 슬러그.
- 근거 문서 → `output/references/<topic-slug>_레퍼런스.txt`, 한국어로, 아래 구조를 사용해 작성.

폴더가 없으면 만든다.

### 6. 근거 .txt 작성

이 하우스 스타일을 따른다(`output/references/gdweb/Airbnb_기업소개페이지_GDWEB_디자인레퍼런스.txt`와 일치):

```
<컨셉/주제> 디자인 레퍼런스
(수집일: YYYY-MM-DD | 입력: design-concept 문서 <URL>  또는  채팅 키워드 "...")

■ 조사 방법
- 사용한 갤러리와 검색어
- 무엇을 포함 / 제외했는지 기준 (매체, 무드 일치도, 최신성)

■ 선정 레퍼런스 (N건)
1. <이름> — <한 줄 요약>
- 갤러리 / 제작자:
- 상세페이지 URL:
- 실제 사이트 URL: (있으면)
- 매체 / 표현방법:
- 주색상: (눈에 띄면)
- 이 컨셉에 맞는 이유: <무드 키워드 연결 + 색 / 타이포 / 레이아웃 근거>
- 로컬 저장 경로: output/references/image/<slug>/NN_....png
...

■ 종합 제안
- 이 레퍼런스들에서 공통적으로 가져올 방향 (레이아웃 / 컬러·무드 / 타이포)
- 색상 확정은 사용자 최종 컨펌 필요 (design-concept 문서가 있으면 그 팔레트 우선)

■ 참고: 검토했으나 제외한 결과
- <이름> — 제외 사유
```

### 7. 보고

사용자에게 준다: `.txt` 경로, 스크린샷 폴더 경로와 파일 목록, 그리고 레퍼런스들이 가리키는 방향에 대한 3~4줄 요약. 한국어로 보고한다.

## 하지 말 것

- 읽기만 한 레퍼런스를 돌려주지 마라 — 모든 선정에는 직접 캡처한 실제 스크린샷이 필요하다.
- 잘라낸 무드 조각이나 단색 스와치를 모으지 마라. 이 스킬은 완결된 레이아웃 / 완성된 작업물을 위한 것이다.
- 어느 갤러리에서도 로그인, 가입, "모두 동의" 쿠키 배너 수락을 하지 마라.
- 주제만으로 매치하지 마라 — 업종은 맞지만 무드가 틀린 레퍼런스는 미스다. 포함하지 말고 제외 섹션에 그렇게 적어라.
- 소스 파일(PPTX, ZIP, 폰트)을 다운로드하지 마라 — 사용자가 명시적으로 요청하고 승인하지 않는 한 스크린샷만.
- 팔레트를 지어내지 마라. design-concept 문서가 있으면 그 팔레트가 우선이고, 없으면 색 방향은 사용자가 확인할 관찰로 남겨둔다.
