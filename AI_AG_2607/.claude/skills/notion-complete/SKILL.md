# notion-complete: Notion "완료작업" DB 저장

사용자가 이미 끝낸 작업을 파싱해서 Notion "완료작업" 데이터베이스에 완료 기록 한 줄로 저장하는 스킬이다. 번들된 `scripts/notion_complete_log.py` 의 함수를 그대로 쓴다 — Notion 저수준 요청 JSON 을 매번 직접 조립하지 않는다.

이번 버전은 **새 완료 기록 저장만** 다룬다. 기존 기록 조회·수정·삭제는 범위 밖이며, 사용자가 그런 요청을 하면 이 스킬이 저장만 지원한다는 걸 알리고 어떻게 도울지 되묻는다.

## 사전 조건

- 프로젝트 루트 `.env` 에 `NOTION_API_KEY` 가 있어야 한다 (통합 토큰, `ntn_` 또는 `secret_` 로 시작). 없으면 사용자에게 알리고 `output/guides/notion-db-api-setup.md` 를 참고하라고 안내한다.
- "완료작업" DB ID 는 스크립트에 기본값으로 박혀 있다. 다른 DB 를 쓰려면 `.env` 에 `NOTION_COMPLETE_DB_ID=` 를 넣으면 그 값이 우선한다.

## "완료작업" DB 스키마 (2026-08 기준)

| 속성 | 타입 | 설명 |
|------|------|------|
| `이름` | title | 완료한 작업 이름 (필수) |
| `담당자` | rich_text | 그 작업을 한 사람 |
| `소요기간` | rich_text | 걸린 기간/시간 (자유 텍스트, 예 `"3일"`, `"2시간"`, `"8/20~8/27"`) |
| `자료 위치` | url | 산출물·자료 링크 (http/https 형태) |

작업 시작 시 `get_schema()` 로 실제 스키마를 한 번 확인한다. 속성 이름/타입이 위 표와 다르면 사용자에게 알리고, 바뀐 이름에 맞춰 값을 넣는다 (스크립트의 `P_NAME` 등 상수를 그 자리에서 맞게 조정).

## 전체 흐름

1. **완료 정보 파악** — 사용자 요청(또는 방금 마친 작업)에서 작업 이름, 담당자, 소요기간, 자료 위치를 뽑는다.
   - 작업 이름(`이름`)이 없으면 저장 전에 되물어본다. 다만 대화에서 방금 끝낸 작업이 명확하면 그걸 한 줄로 요약해 제안하고 확인받는다.
   - `담당자`: 사용자가 본인이 한 것으로 말하면 사용자 이름/"본인"을 넣되, 이름을 모르면 지어내지 말고 비워두거나 물어본다.
   - `소요기간`: "3일 걸렸어", "이번 주 내내" 같은 표현을 그대로 짧게 정리해 넣는다. 언급이 없으면 비워둔다.
   - `자료 위치`: 산출물 URL(구글 독스, 노션 페이지, 드라이브, PR 링크 등)이 확인되면 넣는다. `url` 타입이라 반드시 `http://` 또는 `https://` 로 시작해야 한다. 링크가 아니면(예: "내 PC 바탕화면") 넣지 않고 사용자에게 알린다. 모르면 지어내지 않는다.

2. **저장 실행** — `scripts/notion_complete_log.py` 의 `add_done(...)` 를 호출한다 (아래 "스크립트 사용법").

3. **결과 보고** — 성공하면 반환된 페이지의 `url` 을 사용자에게 전달하고, 실제로 저장된 작업 이름/담당자/소요기간/자료 위치를 요약해 알린다. 1번에서 제안·가정한 부분이 있으면 명시한다.

## 스크립트 사용법

한글이 인자·리터럴로 들어가므로, **셸 명령줄에 한글을 직접 넘기지 않는다.** 대신:

1. Write 도구로 입력값을 담은 JSON 파일을 스크래치패드에 만든다 (경로는 ASCII).
2. 그 JSON 경로만 인자로 넘겨 스크립트를 실행한다.

```json
// C:\...\scratchpad\notion_complete_input.json
{
  "name": "3분기 실적 보고서 작성",
  "owner": "본인",
  "duration": "3일",
  "location": "https://docs.google.com/document/d/xxxx"
}
```

여러 건이면 위 객체들의 배열로 만든다.

```bash
python .claude/skills/notion-complete/scripts/notion_complete_log.py C:/.../scratchpad/notion_complete_input.json
```

또는 Write 로 작은 파이썬 실행 파일을 만들어 함수를 직접 호출해도 된다:

```python
import sys
sys.path.insert(0, r"<이 스킬 폴더>/scripts")
from notion_complete_log import load_env, get_schema, add_done

load_env()
# print(get_schema())  # 스키마 확인
page = add_done(
    name="신규 협력사 계약서 검토",
    owner="본인",
    duration="2시간",
    location="https://www.notion.so/xxxx",
)
print(page["url"])
```

- `owner`, `duration`, `location` 은 모두 선택 인자다. 언급이 없으면 넘기지 않는다.
- `location` 은 `url` 타입이라 `http`/`https` 로 시작하는 값만 유효하다.
- 실행 셸은 Bash / PowerShell 어느 쪽이어도 되지만, 인자로 넘기는 파일 경로는 ASCII 여야 한다.

## 오류 대응

- `NOTION_API_KEY 가 .env 에 없습니다` → 사용자에게 `.env` 에 토큰을 넣어달라고 안내.
- `저장 실패 404` → 통합이 이 DB 에 연결(공유)되지 않음. 노션에서 DB 페이지 우상단 `•••` → "연결" → 통합 추가 필요.
- `저장 실패 400` + `is not a property that exists` → DB 속성 이름이 바뀜. `get_schema()` 결과를 사용자에게 보여주고 매핑을 맞춘다.
- `저장 실패 400` + `url` 관련 메시지 → `자료 위치` 값이 URL 형식이 아님. `http`/`https` 로 시작하는지 확인.
- `저장 실패 429` → 잠시 후 재시도 (Notion 레이트리밋, 평균 3req/s).

## 하지 말아야 할 것

- 작업 이름이 불분명한데 임의로 지어내 저장하지 않는다 — 방금 끝낸 작업이 있으면 요약해 확인받고, 없으면 되묻는다.
- 담당자·자료 위치를 추측해서 지어내지 않는다 — 확인 안 되면 비워둔다.
- URL 이 아닌 값을 `자료 위치` 에 넣지 않는다.
- Notion API 요청 JSON 을 직접 조립하지 않는다 — `notion_complete_log.py` 함수를 쓴다.
- 조회·수정·삭제 요청을 저장으로 오인하지 않는다 — 이 스킬은 새 완료 기록 저장만 한다.
- 아직 진행 중인(마감 남은) 업무는 `notion-work`, 개인 약속은 `notion-personal`, 학습·조사 기록은 `notion-study` 로 넘긴다.
