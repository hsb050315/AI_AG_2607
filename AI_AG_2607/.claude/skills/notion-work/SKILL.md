# notion-work: Notion "업무" DB 저장

사용자가 말한 업무 항목을 파싱해서 Notion "업무" 데이터베이스에 새 행으로 저장하는 스킬이다. 번들된 `scripts/notion_work_task.py` 의 함수를 그대로 쓴다 — Notion 저수준 요청 JSON 을 매번 직접 조립하지 않는다.

이번 버전은 **새 업무 저장만** 다룬다. 기존 업무 조회·수정·삭제·완료 처리는 범위 밖이며, 사용자가 그런 요청을 하면 이 스킬이 저장만 지원한다는 걸 알리고 어떻게 도울지 되묻는다.

## 사전 조건

- 프로젝트 루트 `.env` 에 `NOTION_API_KEY` 가 있어야 한다 (통합 토큰, `ntn_` 또는 `secret_` 로 시작). 없으면 사용자에게 알리고 `output/guides/notion-db-api-setup.md` 를 참고하라고 안내한다.
- "업무" DB ID 는 스크립트에 기본값으로 박혀 있다. 다른 DB 를 쓰려면 `.env` 에 `NOTION_WORK_DB_ID=` 를 넣으면 그 값이 우선한다.

## "업무" DB 스키마 (2026-08 기준)

| 속성 | 타입 | 설명 |
|------|------|------|
| `이름` | title | 업무 제목 (필수) |
| `등록일` | date | 업무를 등록/시작한 날. 보통 **오늘 날짜**를 넣는다 |
| `잔여기한` | date | 마감일 (deadline) |
| `제출처` | rich_text | 제출 대상 — 팀, 담당자, 채널 등 |

작업 시작 시 `get_schema()` 로 실제 스키마를 한 번 확인한다. 속성 이름/타입이 위 표와 다르면 사용자에게 알리고, 바뀐 이름에 맞춰 값을 넣는다 (스크립트의 `P_NAME` 등 상수를 그 자리에서 맞게 조정).

## 전체 흐름

1. **업무 정보 파악** — 사용자 요청에서 제목, 등록일, 마감일(잔여기한), 제출처를 뽑는다.
   - 제목이 없으면 저장 전에 반드시 되물어본다.
   - **등록일**: 사용자가 따로 말하지 않으면 오늘 날짜(시스템 컨텍스트의 currentDate)를 기본으로 넣는다. 이건 지어내는 게 아니라 "언제 등록했는지"라는 사실이라 합리적인 기본값이다.
   - **마감일**: "다음 주 금요일까지", "9월 5일까지" 같은 표현을 오늘 날짜 기준 실제 날짜로 환산한다. "언젠가", "여유 있게" 처럼 특정할 수 없으면 억지로 추정하지 말고 되물어보거나, 마감 없이 저장하고 그 사실을 알린다.
   - **제출처**: 언급이 없으면 비워둔다 (임의로 지어내지 않는다).

2. **날짜 값 만들기** — Notion date 속성은 `"2026-09-05"` 형식. 기간이 있으면 `"2026-09-01/2026-09-05"` (start/end 를 `/` 로 구분). 업무는 보통 시각까지는 필요 없으니 날짜만 넣는다.

3. **저장 실행** — `scripts/notion_work_task.py` 의 `add_task(...)` 를 호출한다 (아래 "스크립트 사용법").

4. **결과 보고** — 성공하면 반환된 페이지의 `url` 을 사용자에게 전달하고, 실제로 저장된 제목/등록일/마감일/제출처를 요약해 알린다. 1번에서 가정한 부분(예: 등록일을 오늘로 잡음, 마감 없이 저장)이 있으면 명시한다.

## 스크립트 사용법

한글이 인자·리터럴로 들어가므로, **셸 명령줄에 한글을 직접 넘기지 않는다.** 대신:

1. Write 도구로 입력값을 담은 JSON 파일을 스크래치패드에 만든다 (경로는 ASCII).
2. 그 JSON 경로만 인자로 넘겨 스크립트를 실행한다.

```json
// C:\...\scratchpad\notion_work_input.json
{
  "name": "3분기 실적 보고서 작성",
  "registered": "2026-08-28",
  "due": "2026-09-05",
  "submit_to": "경영지원팀 이과장"
}
```

여러 건이면 위 객체들의 배열로 만든다.

```bash
python .claude/skills/notion-work/scripts/notion_work_task.py C:/.../scratchpad/notion_work_input.json
```

또는 Write 로 작은 파이썬 실행 파일을 만들어 함수를 직접 호출해도 된다:

```python
import sys
sys.path.insert(0, r"<이 스킬 폴더>/scripts")
from notion_work_task import load_env, get_schema, add_task

load_env()
# print(get_schema())  # 스키마 확인
page = add_task(
    name="신규 협력사 계약서 검토",
    registered="2026-08-28",
    due="2026-09-02",
    submit_to="법무팀",
)
print(page["url"])
```

- `registered`, `due`, `submit_to` 는 모두 선택 인자다. 언급이 없으면 넘기지 않는다 (단 `registered` 는 위 1번 규칙대로 보통 오늘 날짜를 넣는다).
- 실행 셸은 Bash / PowerShell 어느 쪽이어도 되지만, 인자로 넘기는 파일 경로는 ASCII 여야 한다.

## 오류 대응

- `NOTION_API_KEY 가 .env 에 없습니다` → 사용자에게 `.env` 에 토큰을 넣어달라고 안내.
- `등록 실패 404` → 통합이 이 DB 에 연결(공유)되지 않음. 노션에서 DB 페이지 우상단 `•••` → "연결" → 통합 추가 필요.
- `등록 실패 400` + `is not a property that exists` → DB 속성 이름이 바뀜. `get_schema()` 결과를 사용자에게 보여주고 매핑을 맞춘다.
- `등록 실패 429` → 잠시 후 재시도 (Notion 레이트리밋, 평균 3req/s).

## 하지 말아야 할 것

- 제목이 빠졌는데 임의로 채워 저장하지 않는다.
- 제출처를 추측해서 지어내지 않는다 — 없으면 비워둔다.
- Notion API 요청 JSON 을 직접 조립하지 않는다 — `notion_work_task.py` 함수를 쓴다.
- 조회·수정·삭제·완료 처리 요청을 저장으로 오인하지 않는다 — 이 스킬은 새 업무 저장만 한다.
- 개인 약속/모임은 `notion-personal`, 구글 캘린더 등록은 `gws-calendar` 로 넘긴다.
