# gws-doc: Google Docs 리포트 생성

주제 하나를 받아 (1) 웹 조사 → (2) 저장할 Drive 폴더 확인 → (3) 보고서 구조화 → (4) Google Docs 문서로 직접 조립까지 끝내는 스킬이다. 로컬에 `.docx`를 만드는 게 아니라 `gws` CLI로 사용자의 실제 Google Drive에 문서를 생성한다. 매번 저수준 Docs API JSON을 직접 짜지 말고, 번들된 `scripts/gws_docs_builder.py`의 함수를 그대로 가져다 쓴다 — 표 셀 채우기처럼 인덱스 계산이 까다로운 부분은 이미 이 스크립트가 검증된 방식으로 처리해 준다.

## 전체 흐름

1. **범위 확정** — 주제가 요청에서 충분히 명확하면 바로 진행한다. 대상이 특정되지 않아 정말 모호할 때만 짧게 되묻는다. 애매하지만 합리적으로 가정 가능하면, 가정한 내용을 "유의사항" 절에 적어두고 진행한다.

2. **웹 조사** — WebSearch/WebFetch로 조사한다.
   - 최소 2곳 이상의 출처를 교차 확인한다 (단일 출처는 보고서에 신뢰도가 낮음을 명시).
   - 가격·재고·정책처럼 시간에 따라 변하는 정보는 조사 시점(오늘 날짜)을 반드시 기록한다.
   - 출처 URL은 표나 목록으로 남겨 사용자가 재확인할 수 있게 한다.
   - 검색 결과가 부족하거나 상충되면 억지로 결론짓지 말고 "확인 불가/추가 조사 필요"로 명시한다.

3. **저장할 Drive 폴더 확인 — 반드시 매번 사용자에게 확인한다.** 조사 내용과 무관하게 이 단계는 절대 생략하지 않는다.
   - `find_folders(name_query)`로 사용자가 언급한 폴더명(또는 주제와 관련된 키워드)을 검색해 후보를 보여주고, 사용자에게 어느 폴더에 저장할지 확인받는다. 사용자가 처음부터 폴더명을 지정했다면 그 이름으로 검색해 후보 중 맞는 것을 고르면 되고, 특별히 언급이 없었다면 "어느 폴더에 저장할까요? (비워두면 내 드라이브 최상위에 만듭니다)"처럼 물어본다.
   - `find_folders`는 사용자가 소유하지 않은, 열람만 가능한 폴더도 결과에 섞여 나올 수 있다 (예: 다른 사람이 공유해준 폴더). 이런 폴더를 골라 `create_document`를 호출하면 `insufficientParentPermissions` 오류로 실패한다. 이 오류가 나면 그 사실을 사용자에게 알리고 (본인 소유 폴더가 아니라 쓰기 권한이 없다는 것) 다른 폴더를 고르거나 폴더 없이(내 드라이브 최상위) 만들지 다시 물어본다.
   - 폴더 지정 없이 진행하고 싶다는 답을 받으면 `create_document(title)`을 `folder_id=None`으로 호출한다 (내 드라이브 최상위에 생성됨).

4. **보고서 구조화** — 아래 "보고서 템플릿"을 따른다. 주제 성격에 따라 3번 섹션의 형태(비교표 vs 서술형)는 유연하게 조정하되 큰 골격은 유지한다.

5. **문서 조립** — `scripts/gws_docs_builder.py`를 import해서 조립한다 (아래 "스크립트 사용법" 참고).

6. **결과 보고** — 조립이 끝나면 `get_share_link(document_id)`로 링크를 얻어 사용자에게 전달한다. 로컬 파일 경로가 아니라 이 Google Docs 링크가 최종 산출물이다.

## 보고서 템플릿

```
[제목] (add_title)
(부제: 문서구분 / 조사일자 — add_subtitle)

## 1. 조사 개요 (add_heading level=1)
- 조사 대상, 조사 범위, 비교/판단 기준, 제외 대상을 명시

## 2. 요약 (add_heading level=1)
- 핵심 결론을 2~5문장으로 먼저 제시

## 3. 상세 조사 결과 (add_heading level=1)
- 비교가 필요한 항목(가격, 옵션, 시기 등)은 표(add_table)로 정리
- 서술이 필요한 배경/맥락은 문단(add_paragraph)으로 정리
- 세부 항목이 많으면 add_heading level=2로 소제목을 나누고, 나열식 정보는 add_bullet_list 사용

## 4. 결론 및 추천 (add_heading level=1)
- 조사 결과를 바탕으로 한 실행 가능한 결론

## 5. 유의사항 (add_heading level=1)
- 조사 시점, 정보 변동 가능성, 가정한 내용, 확인 못한 부분, 출처 URL 목록
```

## 스크립트 사용법

`scripts/gws_docs_builder.py`에 있는 함수를 그대로 사용한다. `gws` CLI를 직접 저수준으로 호출하거나 Docs API 요청 JSON을 처음부터 짜지 않는다.

```python
import sys
sys.path.insert(0, "<이 스킬 폴더>/scripts")
from gws_docs_builder import (
    find_folders, create_document, get_share_link,
    add_title, add_subtitle, add_heading, add_paragraph,
    add_bullet_list, add_table,
)

# 1) 저장할 폴더 확인 (사용자에게 반드시 먼저 물어본다)
folders = find_folders("여행")  # 사용자가 언급한 폴더명/키워드
# ... 사용자에게 후보를 보여주고 확인받은 뒤 ...
doc_id = create_document("OO 조사 보고서", folder_id=folders[0]["id"])  # 또는 folder_id=None

add_title(doc_id, "OO 조사 보고서")
add_subtitle(doc_id, "문서구분: 내부 보고용 | 조사일자: 2026년 8월 23일")

add_heading(doc_id, "1. 조사 개요", level=1)
add_paragraph(doc_id, "...")

add_heading(doc_id, "3. 상세 조사 결과", level=1)
add_table(doc_id, headers=["항목", "가격", "비고"], rows=[["A", "10,000원", "-"]])
add_bullet_list(doc_id, ["항목 하나", "항목 둘"])

add_heading(doc_id, "4. 결론 및 추천", level=1)
add_paragraph(doc_id, "...")

print(get_share_link(doc_id))
```

- 모든 `add_*` 함수는 문서 맨 끝에 순서대로 이어 붙인다 — 반드시 위에서부터 아래 순서로 호출한다.
- `create_document`가 `insufficientParentPermissions`로 실패하면 폴더 권한 문제다 (해당 폴더가 사용자 소유가 아님). 사용자에게 알리고 다른 폴더를 다시 물어본다.
- 새 종류의 콘텐츠(예: 이미지 삽입, 링크 삽입)가 필요하면 이 파일에 함수를 추가하는 방식으로 확장한다 — 매번 인라인으로 저수준 JSON을 조립하지 않는다.

### 한글(비-ASCII) 텍스트를 다룰 때 주의할 점

문서 제목/본문/표 내용 대부분이 한글이므로, 이 함수들을 호출하는 파이썬 코드를 실행할 셸 도구 선택이 중요하다.

- **Bash 도구(Git Bash/MSYS)로 한글이 포함된 명령을 실행하면, 파이썬 프로세스가 시작되기도 전에 인자 문자열 자체가 깨진다.** 이는 `gws`나 이 스크립트의 버그가 아니라 Bash 도구가 명령줄을 자식 프로세스에 전달하는 방식 자체의 문제라, 스크립트 쪽에서 고칠 수 없다.
- 한글(또는 다른 비-ASCII 문자)이 포함된 문자열을 인라인 `python -c "..."` 형태로 실행해야 한다면, **Bash 도구 대신 PowerShell 도구를 사용한다.**
- 가장 안전한 방법은 한글 문자열을 명령줄 인자로 아예 넘기지 않는 것이다 — Write 도구로 파이썬 스크립트 파일(.py)을 작성해서 그 안에 한글 리터럴(제목, 본문, 표 내용 등)을 넣고, 그 파일 경로(ASCII)만 셸 명령의 인자로 넘겨 실행한다. 문서 내용이 길수록 이 방식이 인라인 `-c`보다 다루기도 쉽다.

## 하지 말아야 할 것

- 저장 폴더를 묻지 않고 임의로 만들지 않는다 — 이 단계는 매번 반드시 사용자 확인을 거친다.
- 조사 없이 이미 알고 있는 지식만으로 보고서를 채우지 않는다.
- 표가 필요한 데이터(가격 비교, 옵션 나열 등)를 문단으로만 서술하지 않는다.
- `gws` 저수준 명령이나 Docs API 요청 JSON을 직접 짜지 않는다 — `gws_docs_builder.py`의 함수를 사용한다.
