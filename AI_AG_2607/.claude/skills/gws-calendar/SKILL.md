# gws-calendar: Google Calendar 일정 등록

사용자가 말한 내용에서 일정 정보를 뽑아 (1) 필요한 정보가 다 있는지 확인 → (2) 등록할 캘린더 확인 → (3) 실제 Google Calendar에 이벤트 생성까지 끝내는 스킬이다. `gws` CLI로 사용자의 진짜 캘린더에 이벤트를 만든다. 매번 저수준 API 호출을 직접 짜지 말고, 번들된 `scripts/gws_calendar_builder.py`의 함수를 그대로 가져다 쓴다.

이번 버전은 **새 일정 등록만** 다룬다. 기존 일정 조회·수정·삭제는 범위 밖이다 (사용자가 그런 요청을 하면, 이 스킬이 등록만 지원한다는 걸 알리고 어떻게 도와줄지 되묻는다).

## 전체 흐름

1. **일정 정보 파악** — 사용자 요청에서 제목, 날짜, 시간, 소요시간(또는 종료시각), 장소를 뽑는다.
   - 제목과 날짜처럼 핵심 정보가 없으면 등록 전에 반드시 사용자에게 물어본다.
   - 시작 시각은 있는데 소요시간/종료시각이 없으면(예: "내일 3시에 회의") 1시간을 기본값으로 가정하고 진행하되, 사용자에게 등록 결과를 알릴 때 "종료시각은 1시간 뒤로 가정했습니다"처럼 가정한 부분을 명시한다.
   - "오후에", "다음 주 초쯤" 처럼 시각 자체가 뭉뚱그려져 있어 합리적으로 특정 시각을 고르기 어려우면, 억지로 추정하지 말고 되물어본다.
   - 오늘 날짜를 기준으로 "내일", "다음 주 금요일" 같은 상대 표현을 실제 날짜로 환산한다.

2. **시간대 처리** — `get_default_timezone()`으로 사용자 캘린더의 기본 시간대(예: `Asia/Seoul`)를 확인하고, 사용자가 다른 시간대를 명시하지 않았다면 그 시간대의 오프셋을 붙여 RFC3339 시각 문자열을 만든다 (예: `2026-08-24T14:00:00+09:00`).

3. **등록할 캘린더 확인** — 사용자가 특정 캘린더 이름을 언급하지 않았다면 기본(주 캘린더, `calendar_id="primary"`)에 등록한다. 이름을 언급했다면 `find_calendars(name_query)`로 검색해서 맞는 캘린더를 고른다.
   - 검색 결과가 여러 개이거나 하나도 없으면, 사용자에게 후보를 보여주고 확인받거나 재질문한다. 애매한 채로 임의의 캘린더에 등록하지 않는다.

4. **이벤트 생성** — `scripts/gws_calendar_builder.py`의 `insert_event(...)`로 실제 등록한다 (아래 "스크립트 사용법" 참고).

5. **결과 보고** — 등록에 성공하면 반환된 이벤트 리소스의 `htmlLink`를 사용자에게 전달하고, 실제로 등록된 제목/날짜/시간(및 1번 단계에서 가정한 부분이 있다면 그것도)을 요약해서 알린다.

## 스크립트 사용법

`scripts/gws_calendar_builder.py`에 있는 함수를 그대로 사용한다. `gws` 저수준 명령을 직접 조립하지 않는다.

```python
import sys
sys.path.insert(0, "<이 스킬 폴더>/scripts")
from gws_calendar_builder import get_default_timezone, find_calendars, insert_event

tz_offset = "+09:00"  # get_default_timezone()이 "Asia/Seoul"이면 +09:00

# 캘린더 이름이 언급되지 않았다면 이 단계는 생략하고 바로 calendar_id="primary" 사용
# cals = find_calendars("가족")
# ... 사용자에게 후보 보여주고 확인 ...

event = insert_event(
    summary="팀 회의",
    start=f"2026-08-24T14:00:00{tz_offset}",
    end=f"2026-08-24T15:00:00{tz_offset}",
    calendar_id="primary",
    location=None,        # 언급 없으면 생략
    description=None,     # 언급 없으면 생략
)

print(event["htmlLink"])
```

- `insert_event`는 특정 시각이 있는 일정만 다룬다. "하루 종일" 같은 종일 일정 요청이 오면, 이 함수가 아직 지원하지 않는다는 걸 알고 사용자에게 시작/종료 시각을 정해달라고 하거나, 필요하면 `gws calendar events insert --json`으로 `start.date`/`end.date`(시각 없는 날짜만)를 직접 넘겨야 한다.
- 참석자 초대, 알림(리마인더), 반복 일정은 이번 버전 범위 밖이다 — 사용자가 요청하면 현재는 지원하지 않는다고 알린다.

### 한글(비-ASCII) 텍스트를 다룰 때 주의할 점

일정 제목/장소/설명에 한글이 들어가는 경우가 대부분이므로, 이 함수들을 호출하는 파이썬 코드를 실행할 셸 도구 선택이 중요하다.

- **Bash 도구(Git Bash/MSYS)로 한글이 포함된 명령을 실행하면, 파이썬 프로세스가 시작되기도 전에 인자 문자열 자체가 깨진다** (예: "친구" → "ģ��"). 이는 `gws`나 이 스크립트의 버그가 아니라 Bash 도구가 명령줄을 자식 프로세스에 전달하는 방식 자체의 문제라, 스크립트 쪽에서 고칠 수 없다.
- 그래서 한글(또는 다른 비-ASCII 문자)이 포함된 문자열을 인라인 `python -c "..."` 형태로 실행해야 한다면, **Bash 도구 대신 PowerShell 도구를 사용한다.** PowerShell은 같은 문자열을 올바른 인코딩으로 전달한다.
- 더 안전한 방법은 한글 문자열을 명령줄 인자로 아예 넘기지 않는 것이다 — Write 도구로 파이썬 스크립트 파일(.py)을 작성해서 그 안에 한글 리터럴을 넣고, 그 파일 경로(ASCII)만 셸 명령의 인자로 넘겨 실행한다. 이렇게 하면 Bash/PowerShell 어느 쪽으로 실행하든 셸의 명령줄 인코딩 문제를 원천적으로 피할 수 있다.

## 하지 말아야 할 것

- 제목이나 날짜처럼 핵심 정보가 빠졌는데 임의로 채워서 등록하지 않는다.
- 등록할 캘린더가 여러 후보로 애매한데 아무거나 골라 등록하지 않는다.
- `gws` 저수준 명령이나 Calendar API 요청 JSON을 직접 짜지 않는다 — `gws_calendar_builder.py`의 함수를 사용한다.
- 조회·수정·삭제 요청을 등록으로 오인해서 처리하지 않는다 — 이 스킬은 새 일정 등록만 다룬다.
