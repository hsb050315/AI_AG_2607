# docx 리서치 보고서 생성

주제 하나를 받아 (1) 웹 조사 → (2) 보고서 구조화 → (3) `.docx` 조립 → (4) 한국어 `.txt` 동반 생성까지 끝내는 스킬이다. 매번 문서 조립 코드를 새로 짜지 말고, 번들된 `scripts/docx_generator.py`의 함수를 그대로 가져다 쓴다.

## 전체 흐름

1. **범위 확정** — 주제, 조사 시점, 비교 기준 등이 이미 요청에서 충분히 명확하면 바로 진행한다. 정말 모호할 때만 (예: "가격 비교해줘"인데 대상 상품이 특정되지 않음) 짧게 되묻는다. 애매한 부분이 있지만 합리적으로 가정할 수 있으면, 가정한 내용을 보고서의 "유의사항" 절에 명시하고 진행한다 — 매번 되묻는 것보다 사용자 경험이 낫다.

2. **웹 조사** — WebSearch/WebFetch로 조사한다. 다음을 지킨다:
   - 최소 2곳 이상의 출처를 교차 확인한다 (단일 출처 정보는 신뢰도가 낮음을 보고서에 명시).
   - 가격·재고·정책처럼 시간에 따라 변하는 정보는 조사 시점(오늘 날짜)을 반드시 보고서에 기록한다.
   - 출처 URL은 표나 목록에 남겨 사용자가 직접 재확인할 수 있게 한다.
   - 검색 결과가 부족하거나 상충되는 경우, 억지로 결론을 내지 말고 "확인 불가/추가 조사 필요"로 명시한다.

3. **보고서 구조화** — 아래 "보고서 템플릿"을 따른다. 더 풍부한 예시가 필요하면 `references/report_template.md`를 읽는다.

4. **문서 조립** — `scripts/docx_generator.py`를 import해서 조립한다 (아래 "스크립트 사용법" 참고).

5. **출력 및 저장** — `.docx`와 `.txt`를 함께 생성하고, 저장된 절대 경로를 사용자에게 보고한다.

## 보고서 템플릿

주제 성격에 따라 3번 섹션의 구체적 형태(비교표 vs 서술형)는 유연하게 조정하되, 아래 큰 골격은 항상 유지한다:

```
# [주제] 조사 보고서
(부제: 문서구분 / 조사일자 / 작성자)

## 1. 조사 개요
- 조사 대상, 조사 범위, 비교/판단 기준, 제외 대상을 명시

## 2. 요약
- 핵심 결론을 2~5문장으로 먼저 제시 (바쁜 독자가 여기만 읽어도 되게)

## 3. 상세 조사 결과
- 비교가 필요한 항목(가격, 옵션, 시기 등)은 표(add_table)로 정리
- 서술이 필요한 배경/맥락은 문단으로 정리
- 항목이 많으면 우선순위/추천 순으로 정렬

## 4. 결론 및 추천
- 조사 결과를 바탕으로 한 실행 가능한 결론

## 5. 유의사항
- 조사 시점, 정보 변동 가능성, 가정한 내용, 확인 못한 부분을 명시
```

전체 예시는 `references/report_template.md`에 있는 실제 작성 사례(피규어 구매분석 보고서)를 참고한다.

## 스크립트 사용법

`scripts/docx_generator.py`에 있는 함수를 그대로 사용한다. 직접 python-docx로 저수준 조립을 새로 하지 않는다.

```python
import sys
sys.path.insert(0, "<이 스킬 폴더>/scripts")
from docx_generator import (
    new_document, add_title, add_heading, add_paragraph,
    add_bullet_list, add_numbered_list, add_table, add_divider,
    set_margins, add_page_number_footer, save,
)

doc = new_document(main_color="1F4E79")  # 색상 지정 방법은 아래 참고
set_margins(doc)
add_page_number_footer(doc)

add_title(doc, "OO 조사 보고서", subtitle="문서구분: 내부 보고용 | 조사일자: 2026년 8월 6일")

add_heading(doc, "1. 조사 개요", level=1)
add_paragraph(doc, "...")

add_heading(doc, "3. 상세 조사 결과", level=1)
add_table(doc, headers=["항목", "가격", "비고"], rows=[["A", "10,000원", "-"]])

add_heading(doc, "4. 결론 및 추천", level=1)
add_paragraph(doc, "...")

save(doc, "research/OO_조사_보고서.docx")
```

이미 `new_document()`가 제목 40pt / 본문 20pt / 맑은 고딕을 기본 적용하므로 폰트 크기를 따로 지정할 필요는 없다.

### 색상(main_color) 정하기

- 사용자가 특정 색을 요청하면 그 색을 hex로 변환해 사용한다. 한국어 색 이름 예시는 `references/color_reference.md`를 참고한다.
- 색 지정 요청이 없으면 기본값(짙은 남색, `1F4E79`)을 그대로 쓴다. 매번 색을 되물을 필요는 없다.

## 파일명 및 저장 위치

- 저장 폴더: 현재 작업 디렉토리(또는 사용자가 지정한 프로젝트) 안에 `research/` 폴더가 이미 있으면 그 폴더에, 없으면 새로 만들어서 그 안에 저장한다.
- 파일명: `<주제(공백은 언더스코어로)>_조사_보고서.docx` / 동일 basename의 `.txt`.
- 저장 후 두 파일의 절대 경로를 사용자에게 알려준다.

## .txt 동반 생성

`.docx`와 내용이 같은 순수 텍스트 버전을 함께 만든다. 표는 `항목 | 값 | 비고` 같은 파이프 구분 또는 정렬된 텍스트로, 제목/섹션은 숫자와 개행으로 표현한다 (마크다운 문법 `#`, `**` 등은 쓰지 않는다 — 일반 텍스트 편집기에서 바로 읽는 용도). `references/report_template.md`의 예시 파일이 실제 포맷 참고용이다.

## 하지 말아야 할 것

- 조사 없이 이미 알고 있는 지식만으로 보고서를 채우지 않는다 — 이 스킬의 핵심은 "지금 시점" 조사다.
- 표가 필요한 데이터(가격 비교, 옵션 나열 등)를 문단으로만 서술하지 않는다.
- 조사 시점과 정보 변동 가능성을 "유의사항"에서 누락하지 않는다.
