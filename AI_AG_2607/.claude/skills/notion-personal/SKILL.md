# notion-personal: Notion "개인 일정" DB 등록

사용자가 말한 개인 일정을 파싱해서 Notion "개인 일정" 데이터베이스에 새 행으로 등록하는 스킬이다. 번들된 `scripts/notion_personal_schedule.py` 의 함수를 그대로 쓴다 — Notion 저수준 요청 JSON 을 매번 직접 조립하지 않는다.

이번 버전은 **새 일정 등록만** 다룬다. 기존 일정 조회·수정·삭제는 범위 밖이며, 사용자가 그런 요청을 하면 이 스킬이 등록만 지원한다는 걸 알리고 어떻게 도울지 되묻는다.

## 사전 조건

- 프로젝트 루트 `.env` 에 `NOTION_API_KEY` 가 있어야 한다 (통합 토큰, `ntn_` 또는 `secret_` 로 시작). 없으면 사용자에게 알리고 `output/guides/notion-db-api-setup.md` 를 참고하라고 안내한다.
- "개인 일정" DB ID 는 스크립트에 기본값으로 박혀 있다. 다른 DB 를 쓰려면 `.env` 에 `NOTION_PERSONAL_DB_ID=` 를 넣으면 그 값이 우선한다.

## "개인 일정" DB 스키마 (2026-08 기준)

| 속성 | 타입 | 설명 |
|------|------|------|
| `이름` | title | 일정 제목 (필수) |
| `시간` | date | 일정 날짜 또는 날짜+시각 |
| `장소` | rich_text | 장소 (자유 텍스트) |
| `함께하는 사람` | rich_text | 동행자. 여러 명이면 `"김지훈, 박서연"` 처럼 콤마로 |

작업 시작 시 `get_schema()` 로 실제 스키마를 한 번 확인한다. 속성 이름/타입이 위 표와 다르면 사용자에게 알리고, 바뀐 이름에 맞춰 값을 넣는다 (스크립트의 `P_NAME` 등 상수를 그 자리에서 맞게 조정).

## 전체 흐름

1. **일정 정보 파악** — 사용자 요청에서 제목, 날짜, 시각, 장소, 동행자를 뽑는다.
   - 제목과 날짜처럼 핵심 정보가 없으면 등록 전에 반드시 되물어본다.
   - "오후에", "다음 주 초쯤" 처럼 시각/날짜가 뭉뚱그려져 합리적으로 특정하기 어려우면 억지로 추정하지 말고 되물어본다.
   - 오늘 날짜를 기준으로 "내일", "다음 주 금요일" 같은 상대 표현을 실제 날짜로 환산한다 (오늘 날짜는 시스템 컨텍스트의 currentDate 를 쓴다).
   - 장소·동행자는 없으면 그냥 생략한다 (임의로 지어내지 않는다).

2. **`시간` 값 만들기** — Notion date 속성에 넣을 ISO8601 문자열을 만든다.
   - 시각이 없는 하루짜리 일정: `"2026-09-03"`
   - 시각이 있는 일정: 타임존 오프셋까지 붙인다 → `"2026-09-03T10:30:00+09:00"` (한국이면 `+09:00`)
   - 기간 일정: `"2026-09-03/2026-09-05"` (start/end 를 `/` 로 구분)

3. **등록 실행** — `scripts/notion_personal_schedule.py` 의 `add_schedule(...)` 를 호출한다 (아래 "스크립트 사용법").

4. **결과 보고** — 성공하면 반환된 페이지의 `url` 을 사용자에게 전달하고, 실제로 등록된 제목/시간/장소/동행자를 요약해 알린다. 2번에서 가정한 부분(예: 시각을 특정 시각으로 잡음)이 있으면 그것도 명시한다.

## 스크립트 사용법

한글이 인자·리터럴로 들어가므로, **셸 명령줄에 한글을 직접 넘기지 않는다.** 대신:

1. Write 도구로 입력값을 담은 JSON 파일을 스크래치패드에 만든다 (경로는 ASCII).
2. 그 JSON 경로만 인자로 넘겨 스크립트를 실행한다.

```json
// C:\...\scratchpad\notion_personal_input.json
{
  "name": "치과 정기검진",
  "when": "2026-09-03T10:30:00+09:00",
  "place": "서울 강남 미소치과",
  "people": "혼자"
}
```

여러 건이면 위 객체들의 배열로 만든다.

```bash
python .claude/skills/notion-personal/scripts/notion_personal_schedule.py C:/.../scratchpad/notion_personal_input.json
```

또는 Write 로 작은 파이썬 실행 파일을 만들어 함수를 직접 호출해도 된다:

```python
import sys
sys.path.insert(0, r"<이 스킬 폴더>/scripts")
from notion_personal_schedule import load_env, get_schema, add_schedule

load_env()
# print(get_schema())  # 스키마 확인
page = add_schedule(
    name="대학 동기 모임",
    when="2026-09-06T19:00:00+09:00",
    place="홍대 소셜포차",
    people="김지훈, 박서연, 이도윤",
)
print(page["url"])
```

- `when`, `place`, `people` 은 모두 선택 인자다. 언급이 없으면 넘기지 않는다.
- 실행 셸은 Bash / PowerShell 어느 쪽이어도 되지만, 인자로 넘기는 파일 경로는 ASCII 여야 한다.

## 오류 대응

- `NOTION_API_KEY 가 .env 에 없습니다` → 사용자에게 `.env` 에 토큰을 넣어달라고 안내.
- `등록 실패 404` → 통합이 이 DB 에 연결(공유)되지 않음. 노션에서 DB 페이지 우상단 `•••` → "연결" → 통합 추가 필요.
- `등록 실패 400` + `is not a property that exists` → DB 속성 이름이 바뀜. `get_schema()` 결과를 사용자에게 보여주고 매핑을 맞춘다.
- `등록 실패 429` → 잠시 후 재시도 (Notion 레이트리밋, 평균 3req/s).

## 하지 말아야 할 것

- 제목이나 날짜처럼 핵심 정보가 빠졌는데 임의로 채워 등록하지 않는다.
- 장소·동행자를 추측해서 지어내지 않는다 — 없으면 생략.
- Notion API 요청 JSON 을 직접 조립하지 않는다 — `notion_personal_schedule.py` 함수를 쓴다.
- 조회·수정·삭제 요청을 등록으로 오인하지 않는다 — 이 스킬은 새 일정 등록만 한다.
- Google Calendar 등록 요청( "구글 캘린더" 명시 )은 `gws-calendar` 스킬로 넘긴다.
