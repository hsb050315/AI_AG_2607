# gws-gmail: 이메일 작성 및 승인 기반 전송

사용자가 말한 요청사항을 바탕으로 이메일을 작성하고, 두 번의 명시적 확인을 거친 뒤에만 실제로 전송하는 스킬이다. `gws` CLI의 Gmail 리소스(`gws gmail +send`, `gws gmail users drafts ...`)로 Gmail API를 직접 호출한다. 매번 저수준 API 호출을 직접 짜지 말고, 번들된 `scripts/gws_gmail_builder.py`의 함수를 그대로 가져다 쓴다.

## 왜 2단계로 나뉘어 있는가

이메일 전송은 되돌릴 수 없는 행동이다 — 한 번 나가면 취소할 방법이 없다. 그래서 이 스킬은 "초안 작성"과 "실제 전송"을 서로 다른 API 호출로 완전히 분리해 두었다:

1. `create_draft(...)` — Gmail 임시보관함에 초안을 저장만 한다. **아무에게도 전송되지 않는다.**
2. `send_draft(draft_id)` — 1번에서 만든 초안을 실제로 발송한다.

두 함수 사이에 반드시 사용자의 명시적인 채팅 승인이 있어야 한다. 사용자가 이미 "보내줘"라고 요청과 함께 말했더라도, 실제 수신자·제목·본문 내용을 보여주기 전까지는 승인으로 간주하지 않는다 — 사용자가 승인하는 대상은 "메일을 보낸다"는 의도가 아니라 "이 구체적인 내용"이기 때문이다.

## 전체 흐름

1. **요구사항 파악** — 사용자의 요청에서 받는사람, 제목(또는 주제), 본문 내용, 필요시 참조(cc)·숨은참조(bcc)·첨부파일을 뽑는다.
   - **받는사람 이메일 주소는 반드시 사용자가 명시적으로 알려준 것만 사용한다.** 이름만 언급되고 주소가 없으면 절대 추측하거나 지어내지 말고 되물어본다 — 잘못된 사람에게 전송되는 사고를 막기 위함이다.
   - 제목이나 본문 내용이 부족하면 사용자의 요청 취지에 맞게 합리적으로 초안을 작성하되, 사용자가 준 내용을 벗어나는 사실을 지어내지 않는다.
   - 첨부파일 경로가 언급되면 실제로 그 파일이 존재하는지 확인 후 사용한다.

2. **초안 표시 및 1차 승인** — 작성한 받는사람/제목/본문(및 cc·bcc·첨부파일 목록)을 채팅에 그대로 보여주고, 이대로 초안을 만들지 확인받는다. 수정 요청이 있으면 반영해서 다시 보여준다.

3. **Gmail 초안 생성** — 2번에서 확인받은 내용 그대로 `scripts/gws_gmail_builder.py`의 `create_draft(...)`를 호출해 실제 Gmail 임시보관함에 저장한다. 이 시점에는 아직 아무것도 전송되지 않는다. 반환된 `draftId`를 기억해 둔다.

4. **최종 전송 승인** — "이 내용으로 전송해도 될까요?"처럼 명확하게 다시 한번 확인받는다. 사용자가 "응", "보내", "전송", "ok" 등으로 명확히 승인해야 다음 단계로 진행한다. 애매하거나 다른 화제로 넘어가면 전송하지 않고 대기한다.

5. **전송** — 4번에서 승인을 받은 경우에만 `send_draft(draft_id)`를 호출한다. 승인 전에는 절대 호출하지 않는다.

6. **결과 보고** — 전송 완료 여부와 받는사람/제목을 사용자에게 요약해서 알린다. 만약 사용자가 3번 이후 취소하거나 승인하지 않으면, `delete_draft(draft_id)`로 초안을 정리할지 물어보거나 Gmail 임시보관함에 남겨둔다.

## 스크립트 사용법

`scripts/gws_gmail_builder.py`에 있는 함수를 그대로 사용한다. `gws` 저수준 명령을 매번 직접 짜지 않는다.

```python
import sys
sys.path.insert(0, "<이 스킬 폴더>/scripts")
from gws_gmail_builder import create_draft, send_draft, delete_draft

# 3단계: 초안 생성 (아직 전송 안 됨)
draft = create_draft(
    to="alice@example.com",
    subject="회의 일정 안내",
    body="안녕하세요, 다음 주 회의는 화요일 오후 2시로 변경되었습니다.",
    cc="bob@example.com",           # 선택
    attachments=["agenda.pdf"],      # 선택
)
print(draft["draftId"])  # 이후 send_draft에 전달할 id

# --- 여기서 반드시 사용자의 최종 전송 승인을 채팅으로 받는다 ---

# 5단계: 승인 후에만 호출
result = send_draft(draft["draftId"])
print(result["messageId"])
```

- `create_draft(to, subject, body, cc=None, bcc=None, attachments=None, html=False)` — `to`/`cc`/`bcc`는 문자열(쉼표 구분) 또는 리스트 모두 가능하다. `html=True`면 `body`를 HTML 조각으로 취급한다(`<html>`/`<body>` 래퍼 불필요).
- `send_draft(draft_id)` — `create_draft`가 반환한 `draftId`를 그대로 넘긴다. **사용자의 최종 승인 없이 이 함수를 호출하지 않는다.**
- `delete_draft(draft_id)` — 사용자가 전송을 취소했을 때 초안을 완전히 삭제한다 (휴지통이 아니라 즉시 영구 삭제).
- 첨부파일 총합은 25MB 제한이 있다 (Gmail API 자체 제약).

### 한글(비-ASCII) 텍스트를 다룰 때 주의할 점

메일 제목/본문 대부분이 한글이므로, 이 함수들을 호출하는 파이썬 코드를 실행할 셸 도구 선택이 중요하다.

- **Bash 도구(Git Bash/MSYS)로 한글이 포함된 명령을 실행하면, 파이썬 프로세스가 시작되기도 전에 인자 문자열 자체가 깨진다.** `gws`나 이 스크립트의 버그가 아니라 Bash 도구가 명령줄을 자식 프로세스에 전달하는 방식 자체의 문제라, 스크립트 쪽에서 고칠 수 없다.
- 가장 안전한 방법은 한글 문자열을 명령줄 인자로 아예 넘기지 않는 것이다 — Write 도구로 파이썬 스크립트 파일(.py)을 작성해서 그 안에 한글 리터럴(제목, 본문 등)을 넣고, 그 파일 경로(ASCII)만 셸 명령의 인자로 넘겨 실행한다 (PowerShell 또는 Bash 모두 이 방식이면 안전하다).
- 콘솔에 결과를 바로 출력하면 콘솔 인코딩 때문에 한글이 깨져 보일 수 있다 — 실제 데이터는 정상이니, 확인이 필요하면 UTF-8로 파일에 써서 확인한다.

## 하지 말아야 할 것

- **사용자의 명시적인 최종 전송 승인 없이 `send_draft`를 호출하지 않는다.** 이것이 이 스킬에서 가장 중요한 규칙이다 — "메일 보내줘"라는 최초 요청만으로는 충분하지 않고, 실제 내용을 보여준 뒤의 승인이 필요하다.
- 받는사람 이메일 주소가 없는데 이름만으로 추측해서 채우지 않는다.
- 사용자가 준 적 없는 사실이나 약속을 본문에 지어내지 않는다.
- `gws` 저수준 명령이나 Gmail API 요청을 직접 짜지 않는다 — `gws_gmail_builder.py`의 함수를 사용한다.
- 테스트나 확인 목적이라도 실제 제3자 주소로 메일을 보내지 않는다 — 필요하면 사용자 본인 주소로만 확인한다.
